# 服务器开发交接

## 项目目标

xAgent 长期建设公平比较不同 Agent、框架和模型的平台，但评测结果最终服务于自研
Agent 框架的开发、消融和回归验证。

平台固定运行以下闭环：

> 导入数据 → 生成任务 → 选择 Agent → 统一执行 → 自动评分 → 对比分析 →
> 开发自研 Agent → 新版本继续测试。

平台统一维护六类核心对象：数据集、任务、Agent、实验、运行记录和结果。

## 已确定的第一阶段

- 首个数据集：Enginuity Bench。
- 首批对照 Agent：Claude Code 与 Codex。
- 首个任务方向：从 Enginuity Bench 定义一个可自动评分的文档与工程视觉任务。
- 验收目标：能够在平台中导入数据、生成任务、选择两个 Agent、发起运行、自动评分并
  查看真实对比结果。
- 最小闭环跑通后，自研 Agent 作为第三个 Agent 接入同一流程。

## 当前仓库状态

- Python `xagent_eval` 已具备 JSONL 数据加载、确定性评分、Agent 适配、运行记录、汇总
  和比较报告，是可运行的 v0.1 文件型评测骨架。
- `web/` 是本地评测控制台原型，目前使用浏览器 `localStorage` 保存配置。
- Web 尚未连接 Runner，没有后端数据库，也不能启动真实 Agent 或展示真实结果。
- 现有 `CommandAgent` 是单行 JSON 请求/响应桥接，后续需要扩展为可管理文件输入、输出
  产物和完整执行日志的运行适配器。

## 服务器上的下一步

按一条最小纵向链路实施，不先扩充大量数据或页面：

1. 定义六类平台对象及其稳定 ID、版本和关联关系。
2. 增加本地服务与持久化，第一版可使用 SQLite。
3. 让 Web、CLI 和 Runner 共用同一套配置与结果协议。
4. 接入 Enginuity Bench 的小型数据切片，不必先下载或处理完整数据集。
5. 从数据切片生成一个可自动评分的任务。
6. 接入 Claude Code 与 Codex，统一输入、工具、超时、预算和重复次数。
7. 保存日志、轨迹、输出产物、评分明细、耗时、成本和错误。
8. 在 Web 中完成创建实验、查看运行状态和比较结果。

## 建议服务器环境

- Linux，优先 Ubuntu 24.04；
- Python 3.11+ 与 `uv`；
- Node.js 22.13+；
- Git 与 Docker；
- Claude Code、Codex CLI 及各自所需凭据；
- 数据集、运行工作区和结果目录使用独立持久化路径。

凭据只保存在服务器环境或密钥管理中，不进入仓库、任务记录或运行日志。Agent 执行应
逐步迁移到一次性 Docker 工作区；平台服务、数据库和 Agent Runner 保持清晰边界。

## 暂不做

- 不先建设大型公开看板；
- 不先接入大量 benchmark；
- 不先开发复杂多 Agent；
- 不使用脱离平台的临时脚本形成第二套任务、运行或结果格式。
